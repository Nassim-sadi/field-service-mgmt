A full-stack field service management platform: Django + DRF + PostgreSQL on the
backend and a React SPA (Vite, TypeScript, Tailwind, shadcn/ui, TanStack Query)
on the frontend.

## Features

- Authentication and role-based access control with JWT (SimpleJWT). Roles:
  `admin`, `manager`, `technician`, `customer`.
- Server-enforced work order state machine: `NEW -> ASSIGNED -> ACCEPTED -> IN_PROGRESS -> COMPLETED` (+ `CANCELLED`). Illegal transitions return a clear `400`.
- Admin dashboard with stat cards, Recharts charts (workload, status mix, parts consumption, SLA) and a Leaflet/OpenStreetMap map of field locations.
- CRUD admin pages for customers, sites, assets, technicians, parts, work orders, service reports and users, each with list, create/edit dialogs and a details sheet.
- Debounced search and configurable pagination (25 / 50 / 100 per page) on every admin list.
- zod + React Hook Form validation on all admin create/edit forms.
- Confirmation dialogs before all work order state transitions (assign, accept, start, complete).
- Color-coded role badges (Admin, Manager, Technician, Customer).
- Audit logging of every work order state transition.
- Demo seed data with Algerian companies, customers, technicians, tools and locations.
- Public marketing page with a "Report a problem" service request form.

## Prerequisites

- Python 3.12+
- Node.js 20+
- PostgreSQL running locally (default config below)

## Backend setup

```bash
cd backend
python -m venv .venv
.venv\Scripts\activate          # Windows
pip install -r requirements.txt

# Set env vars (or rely on defaults) - e.g. for local Postgres:
#   DB_NAME=fieldservice DB_USER=fieldservice DB_PASSWORD=... DB_HOST=localhost DB_PORT=5432
#   DJANGO_SECRET_KEY=...  (a random one is used if unset)

python manage.py migrate
python manage.py seed_demo        # optional: demo data, admin/adminpass123
python manage.py runserver
```

API docs:

- Swagger: `http://localhost:8000/api/docs/`
- ReDoc: `http://localhost:8000/api/docs/redoc/`
- OpenAPI schema: `http://localhost:8000/api/schema/`

Docs are auto-generated by drf-spectacular from the DRF views.

### Demo login

After `seed_demo`: `admin / adminpass123` (admin).

## Frontend setup

```bash
cd frontend
npm install
npm run dev        # http://localhost:5173
```

Set `VITE_API_URL` (defaults to `http://localhost:8000/api`) if the backend is
not on `localhost:8000`.

Build / lint:

```bash
npm run build      # tsc -b + vite build
npm run lint
```

## Environment variables (backend)

| Variable             | Default                  | Purpose              |
| -------------------- | ------------------------ | -------------------- |
| `DB_NAME`            | `fieldservice`           | Postgres database    |
| `DB_USER`            | `fieldservice`           | Postgres user        |
| `DB_PASSWORD`        | `fieldservice_dev_pass`  | Postgres password    |
| `DB_HOST`            | `localhost`              | Postgres host        |
| `DB_PORT`            | `5432`                   | Postgres port        |
| `DJANGO_SECRET_KEY`  | random                   | Django secret key    |
| `DJANGO_DEBUG`       | `true`                   | Debug mode           |

## State transitions (API)

- `POST /api/work-orders/{id}/assign/` (management) - requires `{"technician": id}`
- `POST /api/work-orders/{id}/accept/`
- `POST /api/work-orders/{id}/start/`
- `POST /api/work-orders/{id}/complete/` (optional report payload)
- `POST /api/work-orders/{id}/reopen/` (management)
